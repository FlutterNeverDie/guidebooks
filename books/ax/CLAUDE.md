# AX 개발자 첫걸음 (books/ax)

독자는 백엔드 개발자(사용자 본인)다. 백엔드 구조와 코딩은 익숙하고, LLM은 써 봤지만 파인튜닝이나 학습 경험은 없다. 목표는 RAG, 청크, 임베딩, 벡터 DB, 온톨로지, 오케스트레이션을 큰 그림에서 이해하는 것이다.

## 형식
- 수학 증명은 쓰지 않는다. 직관과 수치 감각(차원, 메모리, 지연)만 다룬다.
- 짧은 코드는 넣어도 된다(`pre.code`, 10줄 안쪽). 실행할 수 있는 코드는 저장소의 `labs/rag-study`에 두고 본문에서 "직접 해 보기" 상자(`.try`)로 가리킨다. 하네스가 `rag-study/...` 경로가 실제로 있는지 검사한다.
- 비유 상자 이름은 "백엔드로 치면"이다. 비유는 DB 인덱스, 캐시, ETL, API 게이트웨이처럼 백엔드에서 가져온다.
- 그림:글 폭은 1:1.875(`book_cover.js`의 `layout`)이라 그림판이 좁다. 장면은 세로형 `fx.stage(api)`(360x480, 아래 자막 막대)로 그리고 viewBox 밖으로 그리지 않는다. 아이콘·카드·말풍선·입자·타이핑은 `components.js`의 `fx`를 쓴다.
- 비교는 표(`table.vs`)로 쓴다. 좋은 점은 `.good`, 약한 점은 `.poor`로 표시한다.

## 사실 주장
- 벤치마크 순위, 가격, 제품 버전처럼 쉽게 바뀌는 수치는 쓰지 않고 확인하는 방법을 적는다.
- HNSW의 `M`, `ef` 같은 안정된 개념과 이름만 쓴다.
- 실습 결과를 본문에 쓸 때는 실제로 돌린 결과만 쓴다.
- 6권의 ai-native 설명은 그 저장소 코드를 읽고 쓴다. 파일과 심볼 이름은 grep으로 확인한다.
